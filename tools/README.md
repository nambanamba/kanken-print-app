# tools

道具はここに置く。**一時領域に置かないこと**（確認ポイント D-11b。
前任が `scratch` に置いた道具がセッション終了で消えて作り直しになった前例がある）。
**パスは、この `tools/` からの相対で書くこと。**絶対パスを直書きするとフォルダが動いた瞬間に全部止まる。

| 道具 | 使い方 | 何をするか |
|---|---|---|
| `test_gen.js` | `node tools/test_gen.js` | 出題の生成ロジックのテスト |
| `smoke-test.mjs` | `node tools/smoke-test.mjs` | ヘッドレスChromeで1日ぶんを通しで確認 |
| `shot.mjs` | `node tools/shot.mjs` | 画面と印刷物のスクリーンショット |
| `build_quiz.mjs` | **`node tools/build_quiz.mjs`** | ★本の問題を暗号化して `kanken-quiz.enc.js` を作り直す |
| **`publish.mjs`** | **`node tools/publish.mjs "メッセージ"`** | ★★**配信の関門。push はこれを通す**（下記） |
| `check_leak.mjs` | `node tools/check_leak.mjs` | 平文の漏れを走査（`publish.mjs` が中で呼ぶ） |
| `measure_input.mjs` | `node tools/measure_input.mjs 6` | 採点入力の速さを実測（CPUを絞る） |
| `browser.mjs` | （ほかから使う） | playwright の探索・起動 |

## ★★配信は、必ずこれを通すこと

```
node tools/publish.mjs "コミットメッセージ"
node tools/publish.mjs -F メッセージファイル
node tools/publish.mjs --dry          … 検査だけして、commit も push もしない
```

**通らなければ commit も push もしません。**見るのは4つ:

| | 何を見るか |
|---|---|
| ① **検出器の自己試験** | わざと1行仕込んで**鳴るか**。**鳴らない検出器で「漏れ0件」と言わない** |
| ② **平文の漏れ走査** | 追跡ファイル全部（**`.md` 含む**） |
| ③ **除外フォルダの混入** | `公式資料` `元データ` `情報` `書き起こし` |
| ④ **テスト** | `smoke-test` と `test_gen` |

### ⚠️ なぜ `.git/hooks/` ではなく `tools/` に置くのか

**フックは `.git/hooks/` にあり、リポジトリに入りません。クローンし直すと消えます。**
**消えても何も言わないので、「入れたつもり」になります。**
→ **黙って効かなくなり、しかも効いているように見える。**

**これは `check_leak.mjs` が日本語ファイル名を黙って飛ばしていたのと、まったく同じ形です**
（2026-09-11。`git ls-files` が非ASCIIパスをクォートするせいで、
**`作業メモ.md` と `引き継ぎ.md` が丸ごと検査対象外だったのに「37本を走査しました」と出ていた**）。

**`tools/` はリポジトリに入るので、クローンしても消えません。**

⚠️ **フックを併用しても構いませんが、それは保険です。**
⚠️ **★フックは消えることがあります。**次の担当は「フックがあるから大丈夫」と思わないでください。
**フックが無い環境でも守られる形（`publish.mjs`）が本体です。**

### なぜこれが要るのか

**2026-09-11、実際に平文を1件漏らしました**（`dr_25` を外した理由をコードに残すとき、
答えページの解説文をそのまま引用して push した。検証担当が検出）。
**そして同じ日に、検出器の試験用の1行を追跡ファイルに置きかけました。**
**どちらも「正しいことをやっていて、置き場所だけが噛み合っていない」形です。**
**手順で守れなかったものは、手順を強くしても守れません。**

## 本の問題を入れ直すとき

書き起こしの単元が増えたら、**これ1本**でよい。

```
node tools/build_quiz.mjs
```

- **引数なしで、既定の平文フォルダ**（`..\..\司令塔\漢検書き起こし_ドリル\data` と `_ノート\data`）を読む
- **合言葉を聞かれる**ので入れる。⚠️ **引数や環境変数に書かないこと**（コマンド履歴に残ると、リポジトリに書くのと大差なくなる）
- **合言葉は司令塔が持っている。**リポジトリには書かれていない（ハッシュも）

⚠️ **平文はリポジトリに入れないこと。**この道具は、
**平文フォルダがリポジトリの中にあると中止する**ようになっている。

## 照合が通った単元を増やすとき

`kanken-quiz.enc.js` に入っていても、**紙に刷るのは `kanken-verified.js` に載っている単元だけ**。
`司令塔\漢検レビュー\照合記録.md` を読んで、**問題文と答えの両方が実物照合を通ったものだけ**を手で足す。
**機械検査だけ通ったものは足さない**（機械検査は書式の検査であって、中身の検査ではない）。
